## 하나의 패턴

9건이 **전부 같은 모양**이었다.

> 손으로 적은 목록이 있다 → 목록에 없으면 조용히 기본값으로 떨어진다 →
> 그 기본값이 **그럴듯해서** 검사기도 사람도 못 잡는다

`회 활동에 얼마나 만족하시나요?`도 문법적으로 멀쩡한 한국어다. `카페인 섭취량은
어느 수준에 해당하나요?`도 선택지가 5개 붙어 있다. 검사기는 **모양**만 보고
**뜻**은 안 보므로 전부 통과했다. 사용자가 눈으로 보기 전까지 아무도 몰랐다.

### 같은 판정이 여러 곳에 복사되어 있었다

| 결함 | 흩어진 곳 |
|---|---|
| 잔여 접속조사 | 2군데 (`briefSubjectFromContent`, `normalizedObjectLabel`) |
| 메타 표현 | 같은 2군데 |
| `필요` 오분류 | **3군데** (`surveyArchetype`, `detectIntent`, `decisionOption`) |
| 측정 수준 판정 | 2군데 (`measurementLevelFor`, 문항 생성기) |

특히 6번은 하나 고치고 테스트 → 그대로, 둘 고치고 → 그대로, **셋 다 고친 뒤에야**
잡혔다. 중간에 두 번 추측으로 때우려다 틀렸고, 계측으로 전환한 뒤 세 번째를 찾았다.

### 과/와 모호성이 네 번 터졌다

한국어 `과/와`는 나열·비교·단어 일부 셋으로 쓰인다. 글자 하나만 찾는 규칙이
네 곳에서 같은 방식으로 무너졌다(이중질문 검증, 주제어 잔여, 객체 라벨 잔여,
주제어 끝 `과` 오판).

모두 같은 처방으로 정리했다. **`와`·`및`은 안전하게 처리하고 `과`는 건드리지
않는다.** 근거는 한국어 명사가 `와`로 끝나는 일은 거의 없고 `과`로 끝나는 일은
흔하다는 것(학과·성과·효과·결과·치과). 네 군데에 근거를 주석으로 남겼다.

## 구조를 바꾼 것

목록을 늘리는 대신 **닫힌 집합**으로 판정하게 바꿨다.

### `app/survey-subject-tails.ts` (신규)

주제어에서 떼야 할 꼬리 규칙 + fixpoint 루프. 두 추출 경로가 같은 규칙을 쓴다.

fixpoint가 필요한 이유: 꼬리 규칙은 서로의 대상을 새로 노출시킨다.
`학식 만족도 실태 파악을 위한 조사`는 조사 → 위한 → 실태 파악 → 만족도 순으로
네 겹을 벗겨야 `학식`이 남는다. 한 번만 훑으면 첫 겹만 떨어진다. 더 이상 줄지
않을 때까지 반복해 규칙 순서에 대한 의존을 없앴다.

### `app/survey-variable-kind.ts` (신규)

변수명 **접미사**로 무엇을 재는지 판정한다.

```
량·액·비·수  → amount      숫자 직접 입력
빈도·횟수     → frequency   0회/1~2회/…
시간·기간     → duration    구간 선택
학점·점수     → score       숫자 직접 입력
률·율·비율    → ratio       퍼센트 입력
형태·수단·방식 → category    자유응답
여부·유무     → binary      예/아니요
도·감·력      → attitude    5점 척도
그 외        → unknown     자유응답
```

**변수는 무한하지만 접미사는 유한하다.** `카페인 섭취량`을 몰라도 `량`으로
끝나니 수량인 것은 안다. 그래서 목록에 없던 `걸음 수`·`저축액`·`교재비`·`흡연량`도
처음부터 제대로 나온다.

### 변수별 구간 테이블을 쓰지 않은 이유

구간 하나를 정하려면 셋을 알아야 한다.

| 필요 | 예 |
|---|---|
| 단위 | 카페인 → 잔? mg? |
| 범위 | 월 생활비 → 대학생 30~80만원 vs 직장인 100~300만원 |
| 구간 폭 | 학점 → 0.5 단위? 1.0 단위? |

**범위가 응답자 집단에 따라 달라져** 변수명만으로 결정할 수 없다. 그래서
숫자를 그대로 받는다. 지어낸 구간보다 평균·상관 분석에도 낫다.

### 정정 1 — `과` 오탐은 이론상 문제였다

작성 당시 "형태소 분석 없이 못 가른다"고 적었으나, 실제로 발동하는지 재보지
않았다. 이후 `학과·성과·효과·결과·치과`가 들어간 프롬프트 15개로 측정한
결과 **오탐 0건**이었다.

오탐이 나려면 한 문장 안에 `만족|평가` → `과+공백` → `불편|개선|빈도…`가
이 순서로 있어야 하는데, 실제 생성 문항은 그 순서가 나오지 않는다
("음식의 맛과 품질에 얼마나 만족하시나요?"는 만족이 과보다 뒤에 있다).

그리고 `07618be`(메타 표현 제거)가 노출 경로를 없앴다. `학식 만족도 조사
결과 개선 방안`이 조사 대상 `학식`으로 정리되면서 `조사 결과 개선`이 문항
제목에 실릴 일 자체가 사라졌다. 의도한 것은 아니고 부수 효과다.

**교훈: 고칠 목록에 올리기 전에 발동 여부부터 잰다.**

### 정정 2 — 이중질문 "미탐"은 고치면 안 된다

작업 중 규칙이 아래를 놓친다는 것을 발견하고 미탐으로 분류했다.

```
음식의 맛과 품질에 얼마나 만족하시나요?
가격과 양에 얼마나 만족하시나요?
방 상태와 생활 환경에 얼마나 만족하시나요?
```

규칙을 강화하면 어떻게 되는지 측정했다.

```
영향받는 설문: 12 / 16  (75%)
영향받는 문항: 27 / 100 (27%)
```

걸리는 것이 **앱이 스스로 만드는 표준 만족도 문항**이다. 규칙만 강화하면
만족도 설문의 4분의 3이 자기 검증에 걸려 422가 된다. 오늘 고친
`INVENTED_TIMEFRAME`(생성기가 자기 규칙을 위반하던 것)과 같은 자기모순을
새로 만드는 셈이다. 문항 템플릿 27개를 함께 쪼개야 하고, 그러면 설문이
7문항에서 10문항 이상으로 늘어 응답률이 떨어진다.

그리고 고칠 문제인지도 분명하지 않다. 규칙이 지금 잡는 것과 비교하면:

| | |
|---|---|
| `맛` / `품질` | 둘 다 음식 만족도라는 **한 개념의 하위 항목** |
| `만족도` / `불편사항` | **서로 다른 개념** |

지금 규칙은 두 번째만 잡는다. 실무 만족도 조사에서 인접 항목을 묶어 묻는
것은 방법론적 엄밀성과 응답률 사이의 표준적 타협이다. 규칙이 잘 조준되어
있다고 판단해 손대지 않기로 했다.

## 작업 방식에서 효과가 있었던 것

**고치기 전에 규모를 측정한 것.** 매번 프롬프트 10~20개를 돌려 몇 건이
깨지는지 세고 시작했다. 그 덕에 두 번은 방향을 바로잡았고, 한 번은 하지
않기로 결정했다.

**느슨하게 만드는 변경에는 양방향 테스트.** 이중질문 규칙은 발동을 검증하는
테스트가 하나도 없었다. 규칙을 완전히 죽여도 아무도 못 잡는 상태였다.
참양성 6개 + 오탐 8개를 같이 넣었다. 되묻기·경계 검사도 마찬가지로 처리했다.

**실패한 테스트가 설계를 알려준 것.** `조사 뒤는 전부 메타`라는 가정으로
구현했더니 `사용자 조사`·`시장 조사`가 깨져 테스트 2개가 실패했다. 그 실패가
규칙을 두 갈래로 나눠야 한다는 것을 알려줬다.
