## F1 (Critical) — 파서 두 개가 같은 대상을 다르게 읽는다

`학생회 만족도 조사` 한 줄에 대해:

```
survey-context.ts   primaryEntity   = "학생회"      ← 정상
survey-intent.ts    surveyObject    = "회"          ← "학생"을 응답자로 떼어냄
```

결과 화면에 표시되는 조사 대상이 **`회`** 가 됩니다 (`blueprint.evaluationTarget`).

`audienceHead` 목록에 "학생"이 있어서 `학생회`를 `학생`(응답자) + `회`(대상)로 쪼갭니다. 같은 종류:

```
학생 경험 조사   → primaryEntity="학생", surveyObject="경험"
                  (응답자와 대상이 서로 반대로 잡힘)
```

이 건은 진단서에 적은 "의도 파싱이 4개 모듈에 흩어져 각자 추측한다"의 직접 증거입니다. 한쪽을 고쳐도 다른 쪽이 다른 답을 내놓습니다.

**사용자 영향**: 03번 문항 1의 선택지가 `초등학교 / 중학교 / 고등학교 / 대학교·전문대학 / 대학원` 입니다. 대학생 설문에 초등학교 선택지가 나옵니다.

## F2 (Critical) — 요청 방식을 조사 대상으로 오인한다

프롬프트: `리커트 척도로만 만족도 조사해줘`

```
surveyObject = "리커트 척도로만"
```

생성된 문항:

```
1. 리커트 척도로만에 전반적으로 얼마나 만족하시나요?
6. 리커트 척도로만의 접근성에 얼마나 만족하나요?
7. 리커트 척도로만의 정보 안내에 얼마나 만족하나요?
8. 리커트 척도로만의 대기 시간에 얼마나 만족하나요?
9. 리커트 척도로만의 비용 부담에 얼마나 만족하나요?
10. 리커트 척도로만이 더 좋아지기 위해 바라는 점을 적어주세요.
```

**10문항 전부 무의미합니다.** 응답자가 무엇을 평가하는지 알 수 없습니다.

`REQUEST_META_USED_AS_OBJECT` 라는 검증 규칙이 이미 존재하지만([survey-context.ts:451](app/survey-context.ts:451)) `조사하고 싶|설문 만들고 싶|알아보고 싶` 패턴만 봅니다. `~로만 ~해줘` 형태는 통과합니다.

여기엔 두 겹이 겹쳐 있습니다.

1. 사용자 요청("리커트 척도로만")을 조사 대상으로 오인
2. 모델 출력이 `AI 설문 문항 유형이 단조롭습니다`로 폐기되고 로컬 템플릿이 나옴 → 오인된 대상 이름이 템플릿 문항 10개에 전부 박힘

즉 **사용자가 명시적으로 요청한 것("척도로만")을 앱이 거부하고, 거부 대체물이 요청을 오해한 결과를 증폭합니다.**

## F3 (Critical) — 복합 의도 fallback이 프롬프트 전체를 대상 이름으로 쓴다

프롬프트: `카페 이용 경험과 불편을 조사하고 빈자리 안내 기능 도입 수요를 파악` (12문항)

앞 4문항은 정상입니다. 5번부터 깨집니다:

```
5. ‘불편을 조사하고 빈자리 안내 기능’이 얼마나 필요하다고 생각하시나요?
6. ‘불편을 조사하고 빈자리 안내 기능’이 제공된다면 이용할 의향이 어느 정도인가요?
8. 카페 이용 경험과 불편을 조사하고 빈자리 안내 기능 수요의 접근성에 얼마나 만족하나요?
9. 카페 이용 경험과 불편을 조사하고 빈자리 안내 기능 수요의 정보 안내에 얼마나 만족하나요?
10. 카페 이용 경험과 불편을 조사하고 빈자리 안내 기능 수요의 대기 시간에 얼마나 만족하나요?
11. ... 비용 부담에 얼마나 만족하나요?
12. ... 쾌적함에 얼마나 만족하나요?
```

**12문항 중 8개가 깨졌습니다.** 5~6번은 조사 목적 문구("불편을 조사하고")를 기능 이름으로 사용하고, 8~12번은 프롬프트 전문을 대상 이름으로 사용합니다.

`composite_plan_fallback` 경로의 품질이 매우 낮습니다. 이 경로는 골든 픽스처에 있는 대표 케이스인데도 이렇습니다.

## F4 (High) — 수리가 의미 중복 문항을 만든다

프롬프트: `2학기 개편된 교양 과목 만족도 조사`, `src=openai_partial_repair`

```
1. 2학기 개편된 교양 과목에 전반적으로 얼마나 만족하시나요?   ← 수리가 삽입
2. 개편된 교양 과목에 전반적으로 얼마나 만족하나요?           ← 모델 원본
```

같은 것을 두 번 묻습니다. 수리 트리거는 `UNNECESSARY_SCREENING`(불필요한 스크리너)이었고, 스크리너를 제거하면서 만족도 문항을 끼워 넣어 원래 있던 만족도 문항과 겹쳤습니다.

직전 수정에서 **문자열이 완전히 같은 중복**은 막았지만, 표현만 다른 의미 중복은 여전히 통과합니다. `SEMANTIC_DUPLICATE_QUESTION` 검사가 있는데도 수리 결과에는 적용되지 않습니다.

## F5 (Medium) — 사용자 명시 요청과 품질 검사가 충돌한다

`리커트 척도로만` 요청 → 모델이 척도형만 생성 → `AI 설문 문항 유형이 단조롭습니다`로 **거부**.

사용자가 명시적으로 요청한 구성을 앱이 규칙 위반으로 처리합니다. 앞서 고친 `INVENTED_TIMEFRAME` 충돌과 같은 종류(규칙끼리, 또는 규칙과 사용자 의도가 모순)입니다.

`하루 수면 시간 조사`(1문항)도 `AI 설문 분석축이 충분히 구체적이지 않습니다`로 폐기됐습니다. 1문항 설문에 분석축 2개 이상을 요구하는 것은 충족 불가능한 조건입니다. 결과 문항 자체는 정상이었습니다.
